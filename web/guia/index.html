La idea en un minuto

Un modelo lineal es una suma: un número de partida (el intercepto) más un número por cada respuesta (los coeficientes). Si guardamos esos números en un archivo, cualquier navegador puede hacer la suma. No hace falta un servidor con Python: la página es gratis y tus datos no salen del computador de quien la usa.

  1. Tus datosUn archivo CSV
  2. ColabPython entrena el modelo
  3. modelo.jsEl modelo convertido en números
  4. GitHubGuarda tu proyecto
  5. GitHub PagesLa publica en internet

Seis palabras que vas a oír

GitHub
Un sitio para guardar proyectos. Se parece a Google Drive, pero guarda cada versión de cada archivo.
Repositorio
La carpeta de tu proyecto en GitHub. Tu página vive en su carpeta web.
Commit
Guardar un cambio con una nota corta, como «subo mi modelo».
GitHub Actions
Un asistente automático: cuando cambias algo, revisa tu modelo y publica la página.
GitHub Pages
Convierte la carpeta web en una página con dirección propia, gratis.
Colab
Python en el navegador, de Google. No se instala nada.

Crea tu cuenta de GitHub

Antes de la clase · 5 minutos

  1. Entra a github.com/signup.
  2. Escribe tu correo, una contraseña y un nombre de usuario. El usuario será parte de la dirección de tu página: elige algo corto, sin espacios.
  3. Revisa tu correo y escribe el código que te envió GitHub.
  4. Si te pregunta por un plan, elige Free.
  5. Ten a mano también una cuenta de Google (Gmail o la institucional) para usar Colab.

Listo si al entrar a github.com ves tu ícono de usuario arriba a la derecha.

1

Copia la plantilla

5 minutos · en GitHub

La plantilla trae todo listo: la página, el cuaderno y el asistente que publica. Vas a crear tu propia copia.

  1. Con tu sesión iniciada, abre la plantilla:
    github.com/Daniel01010101010101/Ejercicio_ejemplo_machine_learning
  2. Arriba a la derecha pulsa el botón verde Use this template → Create a new repository.
  3. En Repository name escribe un nombre corto sin espacios ni tildes, por ejemplo mi-modelo.
  4. Deja marcado Public. La página gratis solo funciona con repositorios públicos.
  5. Pulsa Create repository.

Listo si arriba a la izquierda dice tu-usuario / mi-modelo.

Si en la pestaña Actions aparece una ejecución con una ✗ roja, es normal: todavía no has activado la página. Se arregla en el paso 2.

2

Activa tu página

7 minutos · en GitHub

Le dices a GitHub que publique la carpeta web. Al terminar tendrás la página del Saber 11 en tu propia dirección; en el paso 3 la cambias por tu modelo.

  1. En tu repositorio, abre la pestaña Settings (la del engranaje, arriba).
  2. En el menú de la izquierda, entra a Pages.
  3. En Build and deployment → Source, elige GitHub Actions. Se guarda solo.
  4. Abre la pestaña Actions. A la izquierda elige Publicar en GitHub Pages.
  5. Pulsa Run workflow y luego el botón verde Run workflow.
  6. Espera uno o dos minutos hasta que aparezca una ✓ verde.
  7. Abre tu página: https://tu-usuario.github.io/mi-modelo/ (tu usuario en minúsculas y el nombre exacto de tu repositorio).

Listo si ves el Predictor Saber 11 funcionando en tu dirección.

3

Entrena tu modelo en Colab

20 minutos · en Google Colab

El cuaderno plantilla hace todo el trabajo de Machine Learning: carga los datos, separa entrenamiento y prueba, entrena, evalúa y convierte el modelo en el archivo modelo.js. Tú solo cambias una celda.

  1. Abre el cuaderno plantilla e inicia sesión con tu cuenta de Google:
    Abrir plantilla_tu_modelo.ipynb en Colab
  2. La primera vez, no cambies nada: el cuaderno usa un ejemplo (precios de diamantes) para que veas el recorrido completo.
  3. Menú Entorno de ejecución → Ejecutar todas (en inglés: Runtime → Run all). Si aparece un aviso de que el cuaderno no es de Google, pulsa Ejecutar de todos modos.
  4. Espera a que termine (menos de un minuto con el ejemplo). En la sección 8 debe decir «OK: JavaScript y scikit-learn coinciden».
  5. Al final se descarga modelo.js. Si el navegador pregunta, permite la descarga.
  6. Con tus datos: cambia la celda 1. Configura y vuelve a Ejecutar todas. Esto es lo que cambias:
# 1. CONFIGURA AQUÍ
TITULO = "Predictor de ..."            # nombre de tu página
PREGUNTA = "¿...?"                     # la frase grande de la portada
AUTOR = "Tu nombre"
URL_DATOS = None                       # None = aparece un botón para subir tu CSV
OBJETIVO = "columna_a_predecir"        # una columna de números
ETIQUETA_OBJETIVO = "Precio"           # cómo se llama en la página
UNIDAD = "pesos"                       # puntos, pesos, %, horas…
# de 3 a 10 columnas (con None, el cuaderno las elige)
VARIABLES = ["col_1", "col_2", "col_3"]

Listo si tienes el archivo modelo.js en tu carpeta de descargas.

Si el archivo quedó como modelo (1).js (pasa cuando descargas dos veces), cámbiale el nombre a modelo.js. La página solo lee ese nombre.

4

Sube tu modelo a GitHub

8 minutos · en GitHub

Reemplazas el modelo.js del Saber 11 por el tuyo. En cuanto lo guardes, el asistente revisa que el modelo sea válido y publica la página de nuevo.

  1. En tu repositorio, pestaña Code, abre la carpeta web.
  2. Pulsa Add file → Upload files.
  3. Arrastra tu modelo.js a la zona punteada (o usa choose your files).
  4. Abajo, pulsa el botón verde Commit changes.
  5. Abre la pestaña Actions y espera la ✓ verde (uno o dos minutos).

Listo si la ejecución más reciente en Actions tiene una ✓ verde.

El archivo tiene que quedar dentro de la carpeta web. Si lo subiste afuera, la página no cambia: bórralo y súbelo otra vez desde la carpeta correcta.

5

Revisa y comparte

5 minutos

  1. Abre tu página y recarga sin caché: Ctrl + F5 en Windows, Cmd + Shift + R en Mac.
  2. Revisa que el título, la pregunta y tu nombre sean los tuyos.
  3. Baja hasta Verificación en tu navegador: debe decir «5 de 5 coinciden». Eso prueba que la página calcula lo mismo que Python.
  4. Cambia respuestas en el formulario y mira qué suma y qué resta cada una.
  5. Comparte tu enlace con un compañero y ábrelo en tu celular.

Listo si otra persona abre tu enlace y ve tu modelo funcionando.

Cómo preparar tus datos

  • Un archivo CSV con una fila por caso y los nombres de las columnas en la primera fila.
  • Una columna de números que quieras predecir (un precio, un puntaje, unas horas). Si es sí/no, usa 1 y 0: el modelo estimará un porcentaje.
  • Entre 3 y 10 columnas que la expliquen. Pueden ser texto (una ciudad, una categoría) o números (una edad, un tamaño): el cuaderno convierte los números en rangos.
  • Desde Excel: Archivo → Guardar como → CSV UTF-8 (delimitado por comas).
  • No incluyas datos personales (nombres, documentos, correos, teléfonos) ni uses para predecir columnas como género o etnia: tu página es pública.

Si algo falla

No veo el botón «Use this template»

Revisa que iniciaste sesión en GitHub. Si aun así no aparece, usa Fork (arriba a la derecha) para crear tu copia. En una copia hecha con Fork, abre Actions y pulsa I understand my workflows, go ahead and enable them antes del paso 2.

Mi página muestra «404»

Espera uno o dos minutos y recarga. Si sigue: revisa que en Settings → Pages la fuente sea GitHub Actions, que en Actions haya una ✓ verde y que la dirección tenga tu usuario en minúsculas, el nombre exacto del repositorio y la barra final.

En «Actions» hay una ✗ roja

Ábrela y mira qué paso falló:

  • «Configurar GitHub Pages» (Get Pages site failed): falta activar la página. Haz el paso 2 y vuelve a pulsar Run workflow.
  • «Prueba de paridad»: el modelo.js no es válido. Vuelve a descargarlo desde Colab y súbelo sin abrirlo ni editarlo.
Subí mi modelo pero la página sigue igual

Recarga sin caché (Ctrl + F5). Revisa que el archivo se llame exactamente modelo.js y que esté dentro de la carpeta web. Mira también que la última ejecución en Actions haya terminado en verde.

Mi repositorio quedó privado

La página gratis necesita un repositorio público. En Settings → General, al final de la página, pulsa Change visibility y elige Public.

Colab dice «No encuentro la columna OBJETIVO» o «no es numérica»

Copia el nombre exacto de la columna desde la tabla de la sección 3 del cuaderno (mayúsculas, tildes y espacios incluidos). El objetivo tiene que ser una columna de números.

Colab dice que mi modelo casi no le gana a la línea base

Tus columnas explican poco lo que quieres predecir. Prueba con otras columnas en VARIABLES, o escribe VARIABLES = None para que el cuaderno elija las que más explican.

No logro correr Colab en clase

Sigue con los pasos 4 y 5 usando el modelo de ejemplo ya listo: en tu repositorio abre ejemplos/diamantes/modelo.js, descárgalo (botón de descarga arriba a la derecha del archivo) y súbelo a la carpeta web.
